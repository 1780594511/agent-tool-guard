# 三分钟演示脚本

先启动前后端。账号默认密码均为 `Demo-Only-2026!`。不要在演示中使用真实公司资料。

**0:00–0:30：可信身份与正常任务**

使用“普通员工”登录。指向可读资源列表，说明来源是服务端会话。点“正常读取”并运行：看到 `read_document`、成功状态、制度内容、call ID 和策略版本。再点“合法敏感任务”创建工单，说明不会因为“密码泄漏/勒索软件”等合法调查词语误拦截。

**0:30–1:10：模型受诱导，但越权止步**

点“文档注入”并运行。第一个调用读到 `pub-injection`，正文中是明显的恶意指令；第二个调用尝试 `hr-001`，被 `RESOURCE_FORBIDDEN` 拒绝。强调模型确实提出了越权操作，安全性来自后端权限判断，不能把本例扩展成“防御全部提示注入”。

**1:10–2:00：审批与实际效果**

点“审批导出”并运行，得到等待审批。审批中心中普通员工没有“批准”按钮。退出，换“独立审批人”登录；查看具体文档、目的地、到期时间和绑定，批准。换回普通员工，在审批中心点“继续执行”。审批变为“已消费”，工作台“我的模拟收件箱”出现实际载荷。

**2:00–2:30：改变参数就不能沿用批准**

再发起一次导出并让独立审批人批准。换回发起人，点“验证参数变更”：界面将同一批准用于另一个允许的模拟目的地，后端仍拒绝 `APPROVAL_BINDING_MISMATCH`，原审批变为已失效，收件箱没有新增条目。新的合法导出必须重新发起申请和审批。

**2:30–3:00：审计和可信评测**

切换“安全管理员”。审计页按 deny 或 export_report 筛选，展开条目，展示 proposal → decision → approval → execution 关联，并验证哈希链。在评测页运行开发集，或展示上一次已完成运行：A/B/C 使用同一 Mock，C 通过全部当前安全断言。明确标注真实模型尚未测，并打开一个 baseline 失败案例展示实际业务状态证据。

准备回答：为什么审批不扩大权限？为什么一个事务能解决本地一致性却不能直接解决外部 API exactly-once？为什么 Mock 的 0% 不代表真实模型通用安全性？
